# Security Policy

## Supported versions

| Version | Supported |
| --- | --- |
| `main` (latest) | Yes |
| Older tags / forks | Best effort |

## Reporting a vulnerability

**Do not** open a public GitHub issue for security problems.

Email **moekyawaung@programmer.net** with:

- Repository name and affected files / URLs
- Description and impact
- Steps to reproduce
- Suggested fix (optional)

Use a clear subject: `[SECURITY] moekyawaung-developer-portfolio-44`.

You may also use **GitHub Security Advisories** on this repository if enabled.

## Response targets

| Stage | Target |
| --- | --- |
| Acknowledgement | 72 hours |
| Initial assessment | 7 days |
| Fix or mitigation (when confirmed) | As soon as practical |

Please avoid publishing exploit details until a fix is available.

## Scope

In scope: XSS in portfolio pages, dependency issues, exposed secrets, insecure headers, open redirects.

Out of scope: social engineering, physical attacks, and denial-of-service against third-party hosts.

## Safe harbor

Good-faith research that follows this policy and does not destroy data or privacy is welcome.
